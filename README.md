# Python program to add annotations to text for *Encyclopedia of the Dog*

Inputs and outputs are stored in the `data` directory.

## Inputs

- chapter data CSV
- annotation data CSV
- raw HTML for the chapter text (individual files)

## Outputs

- annotated HTML for each chapter with YAML front matter for Jekyll site
- CSV report of missed annotations

## What it does

For each chapter, the program gets the relevant annotations from the annotation data CSV (currently `comments-all.csv`), processes them to determine overlap (parent/child relationships), then executes a find-and-replace to add annotation markup to the text. It writes an output file for each chapter consisting of the YAML front matter needed for the Jekyll site and the annotated chapter text in HTML. Finally, it prints a report in the console indicating the percentage of annotations successfully added to the text and writes a CSV file containing the annotations that were missed for diagnostic purposes.

## 2026.05.06 Notes

As of 2026.05.06, the HTML output files have been copied into the _texts directory in the [refactored](https://github.com/digbmc/dogopedia-dev/tree/refactored) branch of [digbmc/dogopedia-dev](https://github.com/digbmc/dogopedia-dev). The dev site is currently being deployed from that branch, so the result of the HTML produced by this program can be viewed at [https://digbmc.github.io/dogopedia-dev/](https://digbmc.github.io/dogopedia-dev/). 

At first glance, the Python program seems to have a lower rate of success replacing annotated text with its marked-up version when compared to the [prod site](https://encyclopediaofthedog.com/), which still uses Liquid to add the annotations to the chapter text.
However, upon closer inspection, while the new Python has missed annotations that the Liquid added, it has also added annotations that the Liquid missed. The report function built into this Python program also makes it easier to check the success rate than the Liquid version, and it should be easier for other developers to work with in the future.

It is worth noting that the program that generates the annotation CSV that this program takes as an input is still being developed, and the data currently in that file has some problems that are causing visible side effects on the dev site. Hopefully, the reports generated by this program will provide useful diagnostic information for the development of the annotation data-generating program.
