# Dogopedia Refactored

## Overview
_Dogopedia Refactored_ is a part of the [_Encyclopedia of the Dog_](https://encyclopediaofthedog.com/) project. _Encyclopedia of the Dog_ is an annotated bilingual digital edition of a Russian novel, hosted on a static website built with [Jekyll](https://jekyllrb.com/). The intended users of _Dogopedia Refactored_ are myself and other developers on the _Encyclopedia of the Dog_ project.

_Dogopedia Refactored_ is designed to replace the original program that adds annotations to the text of each of the chapters in this digital edition. I wrote the original program in Liquid, and it ran during the `build` process for the website. This new version of the program is written in Python and designed to run after the program that writes the annotation data file and before the Jekyll `build` command. It is useful to rewrite this code in Python for several reasons. First, the other developer on the project is more familiar with Python than Liquid. Second, Python has features that make it much better suited for this kind of program than Liquid. Finally, Python is generally more widely used and applicable than Liquid.

As of May 8, 2026, the _Dogopedia Refactored_ output files have been copied into the _texts directory in the [refactored](https://github.com/digbmc/dogopedia-dev/tree/refactored) branch of [digbmc/dogopedia-dev](https://github.com/digbmc/dogopedia-dev). The dev site is currently being deployed from that branch, so the result of the HTML produced by this program can be viewed at [https://digbmc.github.io/dogopedia-dev/](https://digbmc.github.io/dogopedia-dev/). 

This Python program has a slightly lower rate of success replacing annotated text with its marked-up version when compared to the original program, which is still used for the [prod site](https://encyclopediaofthedog.com/). However, the report function built into this Python program makes it easier to check the success rate than the Liquid version, and it should be easier for other developers to work with in the future.

It is worth noting that the program that generates the annotation CSV that this program takes as an input is still being developed, and the data currently in that file has some problems. Hopefully, the reports generated by this program will provide useful diagnostic information for the development of the annotation data-generating program.

## Inputs and Outputs

Inputs and outputs are stored in the `data` directory.

Inputs:
- chapter data CSV
- annotation data CSV (generated by a separate program)
- raw HTML for the text of each chapter

Outputs:
- annotated HTML for each chapter with YAML front matter for the Jekyll site
- CSV reports of missed annotations for each chapter

## How it works

For each chapter, the program gets the relevant annotations from the annotation data CSV (`comments-all.csv`), processes them to determine overlap (parent/child relationships), then executes a find-and-replace to add annotation markup to the text. It writes an output file for each chapter consisting of the YAML front matter needed for the Jekyll site and the annotated chapter text in HTML. Finally, it prints a report in the console indicating the percentage of annotations successfully added to the text and writes a CSV file for each chapter containing the annotations that were missed (for diagnostic purposes).
